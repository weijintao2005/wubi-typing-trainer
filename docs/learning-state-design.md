## 0. 评审摘要

目标是把目前“只统计错字、错字本连对 3 次移出”的简单模型，升级为**按科目记忆学习状态**的出题策略：

1. 每个字库/词库（下称“科目”）独立记录每个字/词的状态：**未出现（new）→ 低频（low）→ 已掌握（mastered）**，出错则进入 **错题（error）**。
2. 第一次出现全对 → 低频；第一次出现有任何错误 → 错题。
3. 重新进入某科目时：**错题与未出现项各约 45%**，**低频项约 10%**（桶级同频，低频更低）。
4. 低频项连续 3 次全对 → 已掌握，此后不再出现在该科目。
5. 错题连续 3 次全对 → 也视为掌握（已确认，沿用原错字本“连对 3 次移出”的行为）。
6. 错字本保留，改为跨科目的“错题视图”，在其中练习会回写所有来源科目。
7. 已掌握项永久排除，提供“重置学习进度”作为退路。

本稿以“按科目独立”为基线；如果改为“按字/词全局共享”，状态机与抽样比例不变，只改数据主键与迁移策略（见第 14 节决策 1）。

**已确认的默认参数**：每轮配额 error 45% / new 45% / low 10%，掌握阈值 `3`，首次正确计入 1/3。

**需要重点确认的 4 组问题**：

- 状态按“科目”独立，还是按字/词全局共享？
- 错题是否也适用“连续 3 次 → 掌握并移出”？
- 提示/跳过是否算错？初学模式是否记录状态？
- 旧错字本数据如何迁移？

## 1. 需求复述

### 1.1 原始规则

| 编号 | 规则 |
| --- | --- |
| R1 | 对每一科练习，一个字/词第一次出现就被正确输入，归入“低频词语” |
| R2 | 只要出现错误输入，归入“错字/错词表” |
| R3 | 重新进入这科练习时，错字错词与从未出现过的字词同频出现；低频词语以较低概率出现 |
| R4 | 低频词语连续 3 次正确，视为已记住，以后的练习中不再出现 |

### 1.2 本设计对规则的落地解释

| 概念 | 定义 |
| --- | --- |
| 科目 | 一个可练习的字库或词库：`jm1/jm2/jm3/jm4/common/common2/gb2312/keyname/chengzi/hard`、`w2/w3/w4`；`errors` 是跨科目视图，不是独立状态科目 |
| 项 | 一个汉字或一个词组，按 `(科目, 文本)` 唯一确定 |
| 首次出现 | 该项在本科目中第一次产生结果（全对或错误）；如果只按 Esc、没有任何错键/提示/跳过，不算出现 |
| 全对 | 本次完成过程中没有错键、没有跳过、没有用提示，且未开启初学模式 |
| 错误 | 本次出现错键、跳过或用提示；错误在发生时立即记录，不要求完成。错键后按 Esc 仍算错误 |
| 连续正确 | 同一项在本科目中连续多次“全对”，任何一次错误清零 |
| 掌握 | 连续正确达到 3 次，状态变为 mastered，本科目不再抽到 |

> 范围说明：本模型只覆盖“看图拆字”的单字库和“词组练习”的词库。字根口诀页的键位反应练习不是字/词项，不纳入本状态系统。

## 2. 现状与差距

### 2.1 现状

- 字库来自 `data/pools.json`，词组来自 `data/words.json`；前端启动时全量加载，按字库洗牌后逐项出题。
- `err_chars` 表只记录“出错的单字”，没有词组、没有科目维度。
- 错字本是一个独立字库，练习时只更新 `err_chars.right_streak`，连续 3 次全对删除该行。
- 普通字库的练习完全随机，不区分“没出现过”“错过”“已经会了”。

### 2.2 差距

| 需求 | 现状 | 需要新增 |
| --- | --- | --- |
| 按科目记忆 | 无 | `item_state` 表，按 `(pool_id, item)` 记录 |
| 首次正确→低频 | 无 | 首次完成判定 + low 状态 |
| 出错→错题 | 仅全局单字 | 按科目、支持词语 |
| 错题与未出现同频 | 无 | 桶级各 45% |
| 低频低概率 | 无 | 桶级 10% |
| 连续 3 次→掌握 | 仅错字本单字 | 状态机统一处理 |
| 掌握后不再出现 | 仅删除 err_chars | 状态 mastered，出题过滤 |

## 3. 状态模型

### 3.1 状态

| 状态 | 含义 | 是否出题 | 每轮目标占比 |
| --- | --- | --- | --- |
| `new` | 本科目从未完成过 | 是 | 45% |
| `low` | 首次完成全对，进入低频 | 是 | 10% |
| `error` | 至少错过一次，或跳过/用提示 | 是 | 45% |
| `mastered` | 连续 3 次全对，已掌握 | 否 | 0 |

`new` 不单独存行：`item_state` 中没有该 `(pool_id,item)` 行即视为 new。

### 3.2 状态转移

| 当前状态 | 本次结果 | 下一状态 | 连对次数 | 其他变化 |
| --- | --- | --- | --- | --- |
| new | 全对 | low | 1 | `seen=1, perfect=1` |
| new | 错误 | error | 0 | `seen=1, error_count=1` |
| low | 全对 | low | +1 | `seen+1, perfect+1`；达到 3 → mastered |
| low | 错误 | error | 0 | `seen+1, error_count+1` |
| error | 全对 | error | +1 | `seen+1, perfect+1`；达到 3 → mastered |
| error | 错误 | error | 0 | `seen+1, error_count+1` |
| mastered | 任意 | mastered | — | 正常不应再被抽到；若出现则忽略 |

```text
                   首次全对
        ┌──────────────────────────┐
        │                          ▼
   ┌────────┐   首次错误      ┌─────────┐  连续 3 次全对   ┌──────────┐
   │  new   │ ──────────────► │  error  │ ───────────────► │ mastered │
   └────────┘                 └─────────┘                  └──────────┘
        │                          ▲   │错误清零                ▲
        │ 首次全对                  │   └───────────────────────┘
        ▼                          │
   ┌─────────┐  连续 3 次全对       │
   │   low   │ ────────────────────┘（low 出错 → error）
   └─────────┘
```

### 3.3 首次出现的判定

首次产生结果时：

- 若首次结果是全对（完成且没有错键/提示/跳过）→ `low`，`right_streak = 1`。
- 若首次结果有错键/跳过/提示 → `error`，`right_streak = 0`，`error_count = 1`。
- 错键后即使改对完成，也已经是 error，不会回到 low。
- 若只按 Esc、且没有任何错键/提示/跳过 → 不写状态，下次仍按 new 处理。
- 若在初学模式下完成 → 不写状态（见 3.5）。

错误在发生时立即上报，不等完成；这样“错键后 Esc”也不会漏记。

### 3.4 “全对”的精确定义

必须同时满足：

1. 本次完成（输入满码）过程中没有错误按键；
2. 没有按“跳过”；
3. 没有主动用空格/按钮看提示；
4. `state.autoHint === false`（初学模式关闭）。

“错误按键后改对再完成”仍算错误，记入错题。

### 3.5 提示、跳过、初学模式

| 操作 | 是否算错 | 说明 |
| --- | --- | --- |
| 错键 | 是 | 第一次错键时立即 POST `error`；同一项后续不再重复上报 |
| 跳过 | 是 | 跳过的同时 POST `error`，然后换题 |
| 空格/按钮看提示 | 是 | 看提示的同时 POST `error`；即使之后全对也记 error |
| 初学模式（始终显示提示） | **不记录** | 界面显示“初学模式：不记录学习进度”；本轮只统计速度/正确率 |
| Esc 中断（无错误/提示/跳过） | 不记录 | 未完成且未出错，不产生状态 |

### 3.6 掌握的两种路径

- `low` 连续 3 次全对 → mastered；
- `error` 连续 3 次全对 → mastered（建议，沿用现有错字本规则）。

一旦 mastered：

- 本科目的后续抽题永久排除；
- 已掌握记录保留在 `item_state`，可统计、可重置；
- 其他科目不受影响（在“按科目独立”方案下）；
- 重置该科目后，该字词回到 new。

### 3.7 示例

以“常用字”科目中的「的」为例：

| 次数 | 结果 | 状态 | 连对 | 说明 |
| --- | --- | --- | --- | --- |
| 第 1 次 | 全对 | low | 1 | 首次全对 |
| 第 2 次 | 全对 | low | 2 | |
| 第 3 次 | 错键后完成 | error | 0 | 清零并进入错题 |
| 第 4 次 | 全对 | error | 1 | |
| 第 5 次 | 全对 | error | 2 | |
| 第 6 次 | 全对 | mastered | 3 | 不再出现 |

## 4. 出题算法

### 4.1 三个候选桶

对科目 `P`，把未掌握的项分成三个互斥的桶：

| 桶 | 内容 | 说明 |
| --- | --- | --- |
| `error` | 状态为 error 的项 | 错字/错词，优先级最高 |
| `new` | 没有状态行的项 | 从未出现 |
| `low` | 状态为 low 的项 | 首次全对，低频 |
| `mastered` | 已掌握 | 不进入候选 |

### 4.2 目标比例（“同频”的落地）

每轮的目标配额按比例分配：

| 桶 | 目标占比 |
| --- | --- |
| error | 45% |
| new | 45% |
| low | 10% |

即：**错题与未出现项的目标出现频率相同**；低频项约为它们的一半以下，符合“较低概率”。
比例是常量，后续可做成设置（低频 10% / 15%；error 与 new 平分剩余）。

> 注意：这是“桶级同频”，不是“每个错题与每个新词的单件概率相同”。后者在错题很少时会让错题几乎不出现（例如 10 个错题对 990 个新词，错题只占 1%），不符合练习目的。

### 4.3 每轮配额计算

设本轮要抽 `N = min(perRound, |error|+|new|+|low|)` 个：

1. 用最大余数法把 `N × (0.45, 0.45, 0.10)` 取整成三个配额 `q_e, q_n, q_l`，总和为 N；
2. 对每个桶取 `take = min(q, |bucket|)`；如果某桶不足，剩余名额进入“待分配”；
3. 把待分配名额按目标比例重新分给还有余量的桶，重复直到分完或所有桶取尽；
4. 如果所有桶取尽仍不足 N，本轮就只出这些（短轮）。

这样：

- 错题少时，所有错题都能进本轮，剩余名额留给新词/低频；
- 新词少时反之；
- 低频在有容量时获得约 10% 的目标份额；某桶不足时按比例重新分配，实际占比可能更高；
- 不会因为某个桶很大而把其他桶挤掉。

### 4.4 桶内抽样

- 每个桶内部**均匀随机、无放回**抽取 `take` 个；
- 三个桶互斥，合并后天然不重复；
- 不需要加权随机公式，逻辑更容易解释与测试。

### 4.5 一轮的行为

- 候选总数 ≥ `perRound`：按 45/45/10 分配，正常抽满；
- 候选总数 < `perRound`：本轮只抽这些，提前结束，结算显示“候选不足，本轮 N 项”；
- 候选总数 = 0：显示“本科目已全部掌握”，提供“重置本科目”，不进入空轮；
- 本轮内某项第 3 次全对变为 mastered：立即从待出题队列删除，本轮不再出现；
- mastered 永远不进入任何桶。

### 4.6 示例

科目有 100 个 error、100 个 new、50 个 low，`perRound = 50`：

- 目标：22.5 / 22.5 / 5 → 最大余数法取整为 23 / 22 / 5；
- error 桶抽 23 个、new 桶抽 22 个、low 桶抽 5 个；
- 桶内各自随机，不重复。

若只有 10 个 error：

- error 桶只能出 10 个，剩余 13 个名额按 45:10 分给 new/low；
- 最终约 10 个 error、33 个 new、7 个 low（具体按最大余数法微调）；
- 这保证“错题少也能全部练到”。

### 4.7 备选方案：单项权重

如果希望“每个错题和每个新词的单件概率完全相等”，可以改为单项权重：

| 状态 | 权重 |
| --- | --- |
| new | 1.0 |
| error | 1.0 |
| low | 0.15 |

每项算 `key = U^(1/w)`，取前 N 个。

- 优点：单件概率严格按 1:1:0.15；
- 缺点：错题总数少时几乎抽不到（10 个错题 / 990 个新词时，错题总占比约 1%），错题得不到足够练习；
- 因此**建议默认用 4.2 的桶级比例**，把单项权重作为可切换的备选。

## 5. 数据模型

### 5.1 新表 `item_state`

```sql
CREATE TABLE IF NOT EXISTS item_state (
    pool_id       TEXT NOT NULL,          -- 科目：common / jm2 / w3 / ...
    item          TEXT NOT NULL,          -- 汉字或词组
    kind          TEXT NOT NULL,          -- 'char' | 'word'
    status        TEXT NOT NULL,          -- 'low' | 'error' | 'mastered'
    right_streak  INTEGER NOT NULL DEFAULT 0,  -- 连续全对次数
    error_count   INTEGER NOT NULL DEFAULT 0,  -- 累计错误次数
    seen_count    INTEGER NOT NULL DEFAULT 0,  -- 累计完成次数
    perfect_count INTEGER NOT NULL DEFAULT 0,  -- 累计全对次数
    first_result  TEXT,                   -- 'low' | 'error'，首次判定
    first_ts      TEXT NOT NULL,
    last_ts       TEXT NOT NULL,
    mastered_ts   TEXT,
    PRIMARY KEY (pool_id, item)
);

CREATE INDEX IF NOT EXISTS idx_item_state_status
    ON item_state (pool_id, status);
```

说明：

- `new` 不建行，节省空间，语义清晰。
- `mastered` 保留行，不删除；方便统计与重置。
- `right_streak` 对 mastered 保留为 3，便于展示。
- `first_result` 用于统计“首次正确率”。
- `error_count` 按“出错的出现次数”计，不按错键次数：一次出现里错 3 个键也只记 1。
- 不存“当前轮”信息，轮次是前端临时状态。

### 5.2 数据量估算

| 数据 | 最大行数 |
| --- | --- |
| 10 个单字库 × 6763 字 | 约 6.7 万 |
| 3 个词库（12000+4519+6000） | 约 2.3 万 |
| 合计 | 约 9 万行（实际只会记录练过的项，远小于上限） |

SQLite 单文件完全够用。

### 5.3 旧数据迁移

现有 `err_chars`（单字、全局）映射到新表：

| 旧字段 | 新字段 |
| --- | --- |
| `char` | `item`，`kind='char'` |
| `count` | `error_count`、`seen_count` |
| `right_streak` | `right_streak`，最大取 2 |
| `last_ts` | `first_ts`、`last_ts` |
| — | `status='error'`、`first_result='error'`、`perfect_count=0` |

迁移策略（建议）：

1. 读取 `pools.json`，找出每个旧错字出现在哪些单字库；
2. 对每个包含它的字库插入一行 `error` 状态；
3. 使用 `INSERT OR IGNORE`，重复迁移不会覆盖新数据；
4. 迁移后 `PRAGMA user_version = 2`；
5. 旧表 `err_chars` 保留不删（作为历史），新代码不再读写。

这样旧的 30 个错字会在所有包含它的字库中以“错题”身份延续，而不是丢失。
副作用：用户没练过的字库也会出现这些错题；因为数量有限（当前 30 个），可以接受，且提供重置。

### 5.4 版本与回滚

- `PRAGMA user_version`：0/1 为旧库，2 为新库。
- 迁移在 `init_db()` 中执行一次，事务提交。
- 回滚：保留旧表即可；新表可删。代码回退到旧版时旧表仍可用。
- 迁移失败：整体回滚，继续用旧逻辑，记录错误日志。

## 6. 接口设计

### 6.1 获取科目学习状态

```
GET /api/learning?pool=common
```

响应：

```json
{
  "pool": "common",
  "counts": { "total": 1000, "new": 620, "low": 300, "error": 12, "mastered": 68 },
  "items": {
    "的": { "status": "low", "streak": 2, "errorCount": 0 },
    "是": { "status": "mastered", "streak": 3, "errorCount": 1 }
  }
}
```

- 只返回该科目有状态的行（new 不返回）。
- 前端用 `total - 行数` 得到 new；`counts` 由服务端算好，避免前端重复计算。
- 最大 6763 行，约 100–200 KB，本机可接受。

### 6.2 上报单次完成

```
POST /api/attempt
Content-Type: application/json

{ "pool": "common", "item": "的", "kind": "char", "result": "perfect", "reason": "ok" }
```

| 字段 | 规则 |
| --- | --- |
| `pool` | 合法科目 id；`errors` 表示错题视图 |
| `item` | 非空，最多 8 字符 |
| `kind` | `char` / `word` |
| `result` | `perfect` / `error` |
| `reason` | `ok` / `wrong` / `hint` / `skip`，仅用于统计 |

响应：

```json
{
  "ok": true,
  "pool": "common",
  "item": "的",
  "status": "low",
  "streak": 1,
  "mastered": false,
  "counts": { "new": 619, "low": 301, "error": 12, "mastered": 68 }
}
```

规则：

- **一次出现只上报一次**：客户端用 `attemptSent` 标记；错键/提示/跳过的第一次立即上报 `error`，完成时不再上报 `perfect`。
- 完成且此前没有上报过 → 上报 `perfect`；按 3.2 状态机推进，达到 3 置 mastered。
- `error`：清空连对，`error_count+1`；首次则进入 error。
- 已 mastered 的项收到请求：幂等返回 mastered，不改变状态。
- 事务内更新，返回最新 counts。

> 为什么错误要立即上报：需求 R2 是“出现错误输入就归入错字表”，错键后按 Esc 也不应该漏记。
> 客户端在错键/提示/跳过时调用一次，之后完成不再调用；这样状态与“本次是否全对”一致。
> 服务端不做请求去重；客户端 `attemptSent` 保证一次出现只上报一次，失败时不自动重试，避免重复计数。

### 6.3 错题视图上报

`pool="errors"` 时，服务端：

1. 查出该 `(item,kind)` 所有 `status='error'` 的来源科目；
2. 对每个来源科目应用同一结果；
3. 返回每个来源的更新结果。

```json
{
  "ok": true,
  "pool": "errors",
  "item": "的",
  "sources": [
    { "pool": "common", "status": "mastered", "streak": 3 },
    { "pool": "jm2", "status": "error", "streak": 1 }
  ],
  "mastered": false
}
```

- 全部来源都 mastered 后，该项从错题视图消失。
- 只更新状态为 error 的来源；某来源如果是 low/ mastered，不受影响。

### 6.4 错题列表

```
GET /api/errors
```

```json
{
  "errors": [
    {
      "item": "的",
      "kind": "char",
      "errorCount": 4,
      "status": "error",
      "sources": [
        { "pool": "common", "streak": 1, "errorCount": 3 },
        { "pool": "jm2", "streak": 0, "errorCount": 1 }
      ]
    }
  ]
}
```

- 按 `(item,kind)` 去重；
- `errorCount` 为各来源求和；
- 供错字本视图和统计页使用。

### 6.5 统计

`GET /api/stats` 增加：

```json
"learning": {
  "distinct": { "mastered": 1200, "low": 300, "error": 40 },
  "pools": [
    { "id": "common", "total": 1000, "new": 620, "low": 300, "error": 12, "mastered": 68 }
  ]
}
```

- `distinct`：按 `(item,kind)` 去重，避免同一字在多个字库重复计数；
- `pools`：按科目统计，用于进度条。

### 6.6 重置

```
POST /api/learning/reset
{ "pool": "common" }   // 省略 pool 表示全部重置
```

- 删除对应 `item_state` 行；mastered/low/error 全部回到 new。
- 不影响 `sessions` 历史统计。
- 不重新导入旧 `err_chars`（迁移只跑一次），避免“重置后又冒出来”。
- 前端必须二次确认。

### 6.7 会话与旧接口

- `POST /api/session` 继续用于一轮的速度/正确率汇总，但**移除 `errors` 数组**，不再 upsert `err_chars`。
- `/api/error-review` 废弃（或保留一个版本的兼容别名，内部转 `/api/attempt`）。
- `/api/errors` 返回结构变更，前端同步升级。

## 7. 前端设计

### 7.1 进入科目

```text
选择科目 / 按 Esc 重开
  └─ GET /api/learning?pool=...
       ├─ 成功：构建 statusMap
       ├─ 失败：降级为“全部按 new 均匀抽”，不记录状态（toast 提示）
       └─ 构建候选：
            ├─ 过滤 mastered
            ├─ 分桶：error / new / low
```

### 7.2 单项完成

```text
题目展示
  ├─ 错键 / 跳过 / 看提示（第一次，且 attemptSent=false）
  │    ├─ POST /api/attempt { result:"error", reason:"wrong|skip|hint" }
  │    └─ attemptSent=true，更新本地状态与提示
  ├─ 完成（输入满码）
  │    ├─ attemptSent=true  → 不再上报（本次已判 error）
  │    └─ attemptSent=false → POST { result:"perfect" }
  ├─ 更新本地 statusMap、counts、徽标
  ├─ 若 mastered：
  │    ├─ 从待出题队列删除
  │    ├─ toast「「X」连续 3 次全对，已掌握」
  │    └─ 若队列为空：结束本轮/提示全部掌握
  └─ 显示状态标签
```

初学模式下不调用 attempt；按 Esc 且未发生错误/提示/跳过时也不调用。

## 8. 错字/错词表与旧错字本

### 8.1 定位

- 每个科目内部：`status='error'` 的项就是该科的错题表。
- 全局错字本：所有科目 error 项的跨科视图，按 `(item,kind)` 去重。
- 没有独立的 `errors` 状态行，避免“错字本里练会了，原科目还是错题”的不一致。

### 8.2 在错字本中练习

- 抽题：所有 error 项等权 1.0（无 new/low）。
- 完成一次全对：所有来源科目 `streak+1`；某个来源达到 3 就 mastered。
- 完成一次错误：所有来源 `streak=0`，`error_count+1`。
- 只要还有一个来源是 error，该项就继续留在错字本。

### 8.3 与旧行为的关系

旧版：错字本连续 3 次全对 → 删除 `err_chars` 行。
新版：错字本连续 3 次全对 → 各来源科目分别达到 3 → 全部 mastered → 自然移出。
行为对用户基本一致，但状态更细、可解释。

## 10. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 首次完成前按 Esc（无错误/提示/跳过） | 不写状态，下次仍是 new |
| 错键后按 Esc | 错键时已上报 error，状态已落库；下次按 error 处理 |
| 错键后改对完成 | 记 error，不因最终正确而变 low |
| 看提示后完成 | 记 error |
| 初学模式 | 不记录状态；只记速度/正确率 |
| 抽到一项后它在别处被掌握（多标签页） | attempt 幂等返回 mastered；前端移出队列 |
| 重置时正在练习 | 重置成功后重开本轮 |
| 数据重建导致某科目项变化 | 状态行保留；不在科目中的行不参与抽取；可选清理 |
| 所有项已掌握 | 显示完成页，提供重置 |
| 候选数 < 每轮字数 | 短轮，结算显示实际项数 |
| 服务端不可用 | 降级为均匀抽题，不写状态；toast 提醒 |
| 旧数据迁移失败 | 事务回滚，保留旧表，toast/日志提示，可手动重试 |
| 同一字在多个科目 | 各科目独立状态；错字本按项去重、回写所有来源 |

## 附录 A：一个完整示例

科目：常用字（1000 项），初始全部 new。

1. 进入科目：抽取 50 项；A 首次全对 → A 变 low(1/3)；B 错键 → B 变 error(0/3)。
2. 再次进入：A 进入低频桶（约 10% 配额），B 进入错题桶（与 new 各约 45%）；B 与 new 同频出现。
3. A 再全对两次 → A mastered，后续不再抽到。
4. B 连对 3 次 → B mastered；若中途错一次，重新计数。
5. 若 B 在错字本中被练习，且 B 同时是 common 和 jm2 的错题，则一次全对会让两个来源都 +1；3 次后两个来源都 mastered。
6. 重置常用字：A、B 等状态删除，回到 new；历史 sessions 不变。

## 附录 B：分桶配额计算示例

以 100 error、100 new、50 low、`perRound = 50` 为例：

1. 目标数：`50 × 0.45 = 22.5`（error）、`22.5`（new）、`5`（low）；
2. 向下取整：22 / 22 / 5，合计 49；
3. 最大余数：error 与 new 的小数部分都是 0.5，任选一个补 1（例如给 error）→ 23 / 22 / 5；
4. 各桶取 `min(配额, 桶大小)`，本例都够，直接桶内随机抽；
5. 若 error 只有 10 个：取 10，剩 13 个名额；按 45:10 分给 new 和 low：
   `13 × 45/55 ≈ 10.6`、`13 × 10/55 ≈ 2.4`，取整后约 11 / 2；最终约 10 / 33 / 7。
6. 若某桶没有余量，继续把剩余名额分给还有余量的桶；全部取尽仍不足 N 则短轮。

桶内抽样是普通随机打乱，不需要权重公式；可预测、易测试。
